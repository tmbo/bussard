Push a device with knx_plan_device: say its summary and what_you_will_notice, show its sentences in full, and call knx_apply_device only after an explicit yes in this conversation. It writes the device's links (group-address and association tables) and the parameter values that differ from your project (one plan sentence each), over KNX Data Secure when the server holds the device's tool key. A plan without the device's product data writes the links only and says why. knx_apply_device runs the write as a job: when it answers `started` with a job id, call knx_apply_status with that job until `done` is true and report its result; a plan whose device read is slow answers `started` the same way, and the finished job's result is the plan to show. knx_last_apply recovers a device's latest result when a reply is lost. knx_restore_parameters replays a parameter backup an apply kept, and knx_restore_tables writes a backup's link tables back (a knx_backup_device run or the pre-write backup an apply kept), with the same plan, explicit yes and job flow; knx_restart_device restarts a device in the form ETS uses, after the human's yes to its question. knx_add_device adds a new device: relay its question (press the programming button), poll knx_job_status until the device is identified, show its sentences and ask its question; after an explicit yes it assigns the address, fetches the product data (download: true is the human's separate yes to the download), writes the device file and reads the device back. knx_commission_line commissions a line: show its plan's sentences and ask its question; one explicit yes starts a job that names each device to press (relay knx_job_status's question), checks the pressed device's order number against the project and assigns its address with a read-back, and waits for the human's retry, skip or stop when they differ; read out its labels at the end. knx_replace_device replaces a dead device with the same product in the same flow: it keeps a backup of the device file and lock record, relays the press-the-button question, and after one explicit yes assigns the address, loads the application, writes the project's parameters and links, reads them back and records the replacement.
