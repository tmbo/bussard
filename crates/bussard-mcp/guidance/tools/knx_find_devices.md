Find the devices on ONE line (`line`, e.g. "1.1") over the bus, as `bussard scan` does (issue #747): probes each address one at a time and reads each responder's mask, manufacturer, order number and serial, over KNX Data Secure when the server's --keyring holds the device's tool key. READ-ONLY on the bus. `from` and `to` narrow the device numbers (default 0 to 255); an absent address costs tens of milliseconds to about 3 s depending on the interface, so a full line can take minutes. Runs as a job: when it ends within a few seconds the call returns the result, otherwise `started: true` and a `job` id for knx_job_status, whose `progress` counts the addresses `probed` and the devices `found` so far. The result has `summary` (one sentence, names first), `devices` (per responder: `name` from the project or null, `address`, `known` (in the project), `mask`, `system_type`, `manufacturer`, `order_number`, `serial`, `secure` for a Data Secure device, `identity` against bussard.lock), `not_in_model`, `missing_from_bus` (the project's devices in the scanned range that did not answer) and `timing`, the same object as `bussard scan --json`. Tell the human the summary. Only available when the server is NOT in passive mode. Each responder the project has carries `support` (issue #1089): whether bussard writes it without the human's override.
