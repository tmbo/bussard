Run the bussard validator and return its diagnostics as JSON (code, severity, message, location, and the `device` and `parameter` a finding names). It runs the same rules as `bussard validate`, parameter values against the product data included (E016, E017, W050); `checked` lists the rule families that ran, and `not_checked` would list any that did not. By default only errors and warnings; `severity: "info"` adds the infos (unlinked objects and similar notes), `severity: "error"` keeps errors only, and `address` ("1.1.4", or "1.1." for a line) or `group` ("3/2/0", or "3/" for a range) narrow it to one device or group. `counts` always counts every error, warning and info in the project, and `note` says what the filter left out. Use this to check whether the project (bussard.toml, groups.toml, devices/*.toml, bussard.lock) is internally consistent, and, with the server's keys, whether secured devices have a tool key and the groups' secure flags match the group keys (addresses only, never a key).
