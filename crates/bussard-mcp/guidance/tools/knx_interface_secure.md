Switch KNXnet/IP Secure of ONE KNX IP interface on or off on the PHYSICAL bus (issue #398), in two calls, as `bussard interface secure on|off` does. Without plan_digest: returns the steps (the security mode and tool key under the device's factory key, then the device authentication code, the password hashes, the tunnelling users and the secured service families under the tool key, and a master reset; `off` undoes it), the credentials the key store would gain (names only), the `question` and a plan_digest. Show the steps to the human and ask the question. With the plan_digest (ONLY after the human's explicit yes in this conversation): saves generated credentials to the key store first, switches, waits out the restart and reads back on a fresh connection; the result says `verified`. Credentials never leave the key store and are never returned. Refused when the server's own session is a KNXnet/IP Secure session with that interface (the restart would end it): the owner runs it in a terminal. Only available with --allow-programming.
