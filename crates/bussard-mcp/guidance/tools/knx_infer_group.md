Infer what a group address IS from the traffic already seen on it: ranked DPT candidates with the reasoning for each, the sending device (address, name, location), its channel and com object (index, name, declared DPT, flags), the project's current entry for the GA, and a proposed human name built from location, channel and com-object function. This is the second half of the learn loop: ask the human to press the button, call knx_wait_for_telegram, then call this. It reads the telegram buffer and the project only and NEVER transmits, so it works in --passive mode. Confidence is never 'high' unless the sending com object declares the DPT. Pass payload_hex to ask about a specific payload instead of the buffered ones. Secured (KNX Data Secure) telegrams count only when the server's --keyring decrypted them (`secured`: true); `undecrypted_secured` counts the ones left out.
