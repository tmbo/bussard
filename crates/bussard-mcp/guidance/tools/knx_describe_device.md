Introspect a physical device over the KNX bus (issue #72): enumerate its interface objects and, for each, every property's DESCRIPTION — PID (with a name when known), data type, element count and read/write access levels. This is READ-ONLY on the bus (it sends A_DeviceDescriptor_Read, A_PropertyValue_Read for object discovery, and A_PropertyDescription_Read; it never writes). Use it to describe an unknown device's property set. On a KNX Data Secure device addressed with its tool key it also returns `security_diagnostics`: the security failures log (sequence, cryptographic and access error counts, the latest failure), the security report and whether the device broadcasts it; read it after a secured write that did nothing. A device without a tool key that refuses the plain walk and answers a secured read under its factory key from the key store is reported `ok: false, factory_key: true` with the reason, as `bussard describe` does: tell the human it needs commissioning in ETS. Rate-limited and only available when the server is NOT in passive mode, since it actively transmits management traffic on the bus.
