Read ONE device's group-address and association tables back over the bus and compare them with its device file, as `bussard reconstruct <address>` does (issue #717). READ-ONLY on the bus. Returns `mask`, `system_type`, `addresses` (the address table), `associations`, `objects` (com-object -> group addresses as resolved from the tables), `table_source`, `notes`, `identity` (the device against bussard.lock), `parameters` (the parameter read-back when bussard.lock pins the product data), `diff` (the raw comparison: `matches` and `note`) and `differences` in the shape knx_diff_project returns: `from`, `to`, `count`, `summary`, `touches_protected`, `sentences` (one per object/group-address pair the device and the project disagree on), `changes`. The same object as `bussard reconstruct <address> --json`, plus `summary` and `next_step`. The tables do not say whether an object sends or listens, so the diff compares group-address sets per object. Quote the sentences to the human. Use it after an apply or a restore, or to see what ETS or another tool left on a device. LINE FORM: pass `line` (e.g. "1.1") instead of `address` to sweep the line (device numbers `from` to `to`, default 0 to 255) and synthesize a fresh project from the tables, as `bussard reconstruct --line` does: written to `out` (a fresh directory relative to the project folder; default captures/reconstructed/line-<line>-<time>), never into the project this server serves. Group names and DPTs are placeholders and every group address is recorded as listen. It runs as a job (about 3 s per address; `started: true` with a `job`: poll knx_job_status) and returns `out`, `devices_found`, `devices_read`, `devices_skipped`, `group_addresses`, `links` and `device_details`. Only available when the server is NOT in passive mode.
