# Cross-crate review

Scope: division of responsibility across the 16 crates and concepts implemented more
than once across crate boundaries. API-level (lib.rs, pub items, signatures, call
counts); deep bodies are the per-crate reviewers' job. Baseline: 137.6k product lines
(loc.py rule). Supporting data: `$CLAUDE_JOB_DIR/tmp/{loc-all,deadpub}.txt`.

Dependency facts (grep of `bussard_x::` per crate, src only):
- cli uses every crate directly: service 56 files, download 15, mgmt 20, transport 17, prod 8, project 5, bus 8.
- mcp likewise: download 9, mgmt 13, transport 7, project 6, bus 6.
- viz: service, model, monitor, mgmt (1), transport (3), bus (3).
- ets is used only by prod (10 files) and project (11); bus by everyone; mgmt by cli/mcp/service/download.
- Surfaces bypass the service layer most in the flash family (call sites of
  `bussard_download::`/`bussard_mgmt::`): cli flash_cmd 27, flash_params 28, plan_cmd 27,
  apply_cmd 23, flash_dump 20, describe_cmd 11; mcp tools_program.rs 38.

## Proposed crate layout and merges

Target: 16 crates to 11. The merges themselves remove little code (lib.rs boilerplate, re-export shims such as prod/application.rs 7 lines, hardware.rs 2, dpt_map.rs 1, flag_map.rs 1, project/{knx_master,manufacturer,hardware,flag_map,dpt_map}.rs 1-9 lines, wrapper error enums, duplicated `Result` aliases: ~500 lines) but they make the concept merges above possible and enforce the layering with Cargo rather than with review.

1. `bussard-transport` absorbs `bussard-bus` (720). The actor is the only way surfaces use the transport; `BusError` (3 variants) folds into `TransportError`; `ops.rs` group read/write moves to service/group.rs. Deletes ~250. Risk: none on the wire.
2. `bussard-product` = `bussard-ets` (3.1k) + `bussard-prod` (3.8k) + the import half of `bussard-project` (project.rs 512, from_json.rs 302, container.rs 218, version.rs 130, build.rs 857) + project/facts.rs (900, derives from the application program). ets is used by nobody else; prod is a thin owner of ets types already (re-exports `dynamic`, `master`). One `ApplicationProgram`, one cache. Deletes ~600 directly (shims, `ProdError` 10 variants vs `EtsError` 7 vs `ImportError` 15 → one), enables the 2,800-line product-model merge. Risk: `bussard-model` must either depend on `bussard-product` (inverting today's prod→model edge: model needs `DynamicSource`, `ApplicationProgram` for validation) or the ets structs move into model. Recommendation: move `ApplicationProgram` and Dynamic (already in model) into model; `bussard-product` keeps parsing, image building and the catalogue.
3. Key store into `bussard-model`: project/keystore.rs 1429 + keyring.rs 670 + password.rs join model/keystore_meta, keyring_checks, secure_links, secure_invariants (716). After this `bussard-project` is empty and goes. Deletes ~400 (two `KeyringExport`s, `KeyStoreMetaError`+`KeyStoreError`+`KeyringError` → one, the `Keyring` intermediate model). Risk: model gains a `bussard-secure` dependency (`Key16`, `Password`); secure is leaf, fine.
4. `bussard-mgmt` stays (the layer-4/APCI protocol layer is clean; connection.rs 1329 is a state machine, not a transport copy). `bussard-download` stays but its five `*_sys7.rs` files (plan_sys7 1405, execute_sys7 671, apply_sys7 468, compute_sys7 254, tables_sys7 333 + mgmt/sys7.rs 378 = 3.5k) are the download reviewer's lever.
5. Surfaces (`cli`, `mcp`, `viz`) depend on `bussard-service` and `bussard-model` only. Today cli imports download/mgmt/prod/project/transport/bus/secure/monitor directly (the flash family: 104 `bussard_download::`/`bussard_mgmt::` call sites in five CLI files, 38 in mcp/tools_program.rs). Enforcing this moves the CLI's flash/plan/apply orchestration (flash_cmd 1066, flash_params 503, flash_dump 498, flash_resident 110, flash_handover 56, param_readback 144, plan_cmd 515, apply_cmd 813: 3.7k) and the MCP's (tools_program.rs 3016, tools_program/flash.rs 718) onto service/flash_flow.rs 647 + flash.rs 249 + download.rs 187 + params.rs 1325, which already claim to be "the one implementation" (model_params.rs header). Est. 4,000 lines once both surfaces are adapters (overlaps with the cli and mcp reviewers' numbers; count once). Risk: this is the write path; the #314 rule says CLI and MCP must call the same function, so this is also the fix for that class of bug. Oracle: every flash row of 95-offline-oracle.sh must stay identical.
6. `bussard-ha` stays (only mcp uses it; cli has an 18-line command). `bussard-monitor` stays (reuses model codec, 2.2k). `bussard-viz` stays but loses enrol duplication.
7. `bussard-testkit` stays as dev-dep; knx-sim (24k, separate workspace) overlaps testkit/device.rs 1326 + sys7.rs + secure_gateway.rs 731 in purpose (a mock device); whether testkit's device can be the sim behind a socket is the small-crates reviewer's call.

Cross-cutting helpers that let the per-crate savings materialise:
- `Report` convention: every service fn returns `Serialize + render_text(Style)`; surfaces never build JSON.
- `ProgressSink` + `Prompt` traits in service (one `Event` enum).
- `ServiceError` with `Refused(String)`; no `Result<_, String>`.
- `resolve_connection` + `ServerConfig` in service.
- `ApplicationProgram` as the one product type; `DeviceFacts` as the one facts record; `KeyStore` as the one key owner.
